1. Objetivo, arquitectura y cobertura

EcoRecicla registra la recolección de residuos en puntos de acopio. El servicio custodia los datos y aplica la seguridad; la aplicación conserva el trabajo del operario cuando no dispone de señal y sincroniza al recuperar la conexión.

EcoRutas (Compose) → ViewModel → SQLDelight / SQLite
Repositorio offline ↔ Ktor / JWT ↔ EcoAPI ↔ PostgreSQL

1.1 Decisiones verificables

La interfaz observa Flow de la base local. Las escrituras se guardan primero en el equipo. El servidor calcula el peso neto y decide autorización y reglas. Docker Compose levanta PostgreSQL y el servicio con un comando. La sesión Android se cifra con AES/GCM y una clave no exportable de Android Keystore.

RequisitoImplementación y verificación

Propósito: demostrar que el acceso depende de una sesión válida y que la restricción RN-02 se hace cumplir en el servicio.

Conclusión: la seguridad se verifica en el backend, aunque la petición se pueda formular desde el cliente.

3. Evidencia offline y reconciliación

E02 · Del ID temporal al ID del servidorEjecutado

Propósito: registrar sin red y recuperar consistencia sin duplicar el trabajo.

Preparación: descargar la ruta real y activar modo avión en el emulador.
Pasos: registrar 24 kg brutos y 2 kg de tara en Empresa Verde 4; recuperar conectividad y sincronizar.
Resultado: la fila quedó pendiente con ID -1; después se sustituyó por el ID positivo y el neto definitivo calculado por EcoAPI.
Conclusión: SQLite conserva la operación y la sustitución se realiza transaccionalmente.
